# 对局提示材料的规则依据

核对日期：2026-09-25。范围是项目已实现的预言家、女巫、猎人、守卫、平民、狼人、狼王、白狼王，以及夜间、警长竞选、发言、放逐、死亡技能和终局流程。未实现的新角色不混入现有对局。

2026-09-26 补充：修复法官播报未进入玩家上下文的问题，仍按事件受众和行动水位裁剪。狼队最多商议两轮，首轮明确刀口和必要分工后可结束；继续判断使用已有行动持久化链路，只识别未决事项，不评价策略质量。补充狼队共有策略、首轮商议要求和公开发言避免复述的建议。

临时六人配置只用于缩短验证时间；人数不改变“首夜行动发生在首次天亮及上警之前”的因果关系。本轮不把它替换成其他平台的六人房间配置。

## 使用资料的原则

1. 官方规则用于核对角色能力和流程，官方攻略用于了解可选打法。攻略作者偏好的打法不能升级为硬规则，也不能成为身份认证。
2. 不存在覆盖所有平台、赛事和房间设置的唯一规则文本。对具体对局，以开局冻结的规则和引擎实际行为为准；与官方房间设置不同的地方明确列出，不能冒充官方统一要求。
3. 主张、操作和结果分开。某人报查验、报药量或承诺退水，只证明他说过；实际提交和系统结算才证明相应操作或结果。
4. 解释行动时使用行动当时的信息。复盘可以用后来证据核验结果，却不能要求当时玩家提前知道，也不能把后来报名补作首夜查验的理由。
5. 硬验收仅检查视角泄露与底层规则、流程错误。站边、信任、收益取舍和语言说服力由模型判断；不因理由不充分、未穷尽分支或与审核者偏好不同而拒绝。技能中的策略建议不构成审核标准。

### 当前引擎约定及官方资料覆盖边界

这些是项目实装约定。提示材料如实说明它们，不能把“与引擎一致”表述为“已经证明是所有官方玩法的唯一规则”。

- 本项目无遗言；官网部分房间有遗言。本项目只在固定窗口询问自爆，不支持任意发言中途插入。
  女巫不能自救写死在引擎里，官网部分房间允许首夜自救。
- 狼队固定两轮商议，提名并列随机，允许空刀；这些操作协议不是上述官网规则页的完整逐字规定。
- 预言家不能重复查验；有合法目标时必须选人，没有目标时跳过。女巫不能毒自己。具体合法选项由引擎生成。
- 警长续选、两次自爆流失、全弃票和无投票人等细节，按当前竞选实现。方向的 `left`/`right` 座位映射、无警长时的起点算法是系统定义。
- 猎人被毒、同守同救时开不了枪，被狼刀、被放逐、被狼王或白狼王带走都能开；狼王被同守同救照样带人，
  这两张牌在这条上不同。被白狼王自爆带走的人当场结算他自己的出局技能。
- 白狼王能带走的只有实际存活的人：夜里被刀或吃毒、死讯尚未公布的人已经出局，选到这样的人这一枪空放。
  这项约束也适用于其触发的猎人、狼王及后续技能连锁；可见候选保留，空放不覆盖夜间死因，不追加技能或胜负结算。
- 每次死亡后先检查终局；终局停止后续技能及交徽。双方同时达成条件时好人胜。这是当前结算优先级，未将官方概括性的胜负说明当作该细节的独立证明。

## 修改覆盖清单

- 角色 skill：`seer`、`witch`、`guard`、`hunter`、`villager`、`werewolf`、`wolf_king`、`white_wolf`，共八份。
- 场景 skill：`day_speech`、`night_action`、`vote`、`sheriff_decide_order`、`wolf_team`、`wolf_discussion`，共六份。
- 规则 skill：`12p_wolf_king`、`12p_white_wolf`、`6p_white_wolf`，共三份。
- 八条模板：生成、审核、修订、摘要各两条；同时检查 `renderPart` 附加说明、动态题面、可见材料和工具说明。
- 复盘生成定义；玩家汇总附本人的原始证据和单步意见，保留原引用编号。业务链不接独立内容评分裁判。
- 数据库启用中的十八个 agent 已检查，当前人设记忆正文为空，无额外文案需要迁移。

本文件供维护者核对来源，不由运行时 skill 加载器注入玩家上下文。技能名称沿用项目路径契约，不因通用 skill 命名建议改动加载接口。

## 验证与生效

工程测试检查合法选项、流程、信息边界、模板装配、引用还原和续跑。它们不证明 LLM 每次输出正确；若实际使用中发现明确的视角泄露或规则错误，针对该缺陷修复并回归，不因主观评价分歧重复校准或重跑整局。

本地模板是平台不可用时的回退正文。使用 Langfuse 时必须同步平台 `production` 模板版本并读回核验，不能只改本地文件。Skill 随 API 构建，进程内会缓存；已运行对局的冻结证据不得改写为新版材料。新进程、新对局才用于验证新版 skill。

Langfuse 保存证据并运行复盘生成。原生评价器接口的 `score` 仅表示材料是否可分析，正文放在 `reasoning`；它不是玩家分数，也不证明主观策略评价正确。引用校验只确保能定位材料，不代替规则检查。

当前平台生成系统模板为 v4、审核系统为 v3、审核用户为 v4、修订系统为 v4；其余四条未变，八条均与本地正文读回一致。复盘生成已更新为 v9，独立内容裁判规则已停用。未启用的格式3重排、内容裁判定义及实验输入装配已移出业务源码；新证据继续使用格式2，既有冻结证据保持原样。发布记录见本地 `docs/rebuild/review-quality/scope-turn-prompt-release.json` 和 `scope-review-release.json`。
